Stage 1 · Where data comes from

Data Entry — four sources feed the platform

Every number on a dashboard ultimately starts in one of these places.

Team Data Entry

  • Prospects, companies, contacts
  • Meetings & Minutes of Meeting (MoM)
  • Actions / follow-ups, opportunities
  • Partnerships & RFP records
React forms → secure /api endpoints, one pipeline for Prospects and a fully separate one for Partnerships.

Bulk Uploads

  • CSV import of prospects & lists
  • Document uploads (MoM attachments, RFP files stored safely in the database)
  • KPI monthly submissions
Every upload is validated row-by-row before saving.

Microsoft 365 Integration

  • Connect Outlook mail & calendars via company login (OAuth)
  • Scheduled meetings land in the Meetings view
  • Send follow-up emails from within PursuitNova
Refresh tokens are encrypted at rest; each user connects their own mailbox.

External Feeds

  • Currency rates — exchangerate-api.com refreshes FX rates once per day automatically
  • Admin can also set FX rates by hand if the feed is down
This is what lets a deal in INR, GBP or EUR roll up into one corporate currency.
↓HTTPS request · JSON payload · session cookie + CSRF token
Stage 2 · The gate

API & Security Gateway — nothing reaches data without passing five checks

SessionJWT cookie login, optional MFA
CSRF checktoken proves the request came from the app
Role permissionSuper Admin → BD Executive, 8 roles
Data scopeself / team / all — managers see their reporting tree
Field-level rulese.g. Presales cannot view final deal amounts

FastAPI backend (~130 endpoints). Every read and write — not just edits — passes this gate, and every action is written to an audit log.

↓validated business operation
Stage 3 · The brain

Business Processing — calculations and automation applied to raw entries

Currency Normalization (FX)

  • Each deal keeps its local currency
  • Daily rates convert everything to the corporate currency
  • Region-based defaults assigned to new prospects
Guarantees like-for-like revenue totals across countries.

Pipeline & Forecast Math

  • Weighted value = amount × win probability
  • Stage-based pipeline rollups
  • Targets vs actuals by owner and region

KPI Engine

  • Monthly templates, targets & actuals per person
  • Submission → admin review → feedback loop

Workflow Automation

  • Rules generate notifications (overdue actions, stage changes)
  • Business + security audit trail on every event
↓SQLAlchemy transactions
Stage 4 · The source of truth

Central Database — PostgreSQL in production (~50 tables)

Revenue pipeline

  • Companies → Contacts → Leads (prospects)
  • Meetings & MoM → Actions
  • Opportunities + teams → forecast data

Parallel pipelines

  • Partnerships: independent company→opportunity chain (cannot affect Prospect reporting)
  • RFPs with secured document storage
  • Supplier Network targets

People, performance & control

  • Users, roles, permissions, org hierarchy
  • KPI templates / targets / actuals / submissions
  • FX rates, org settings, notifications, saved views
  • Audit logs & security logs

One database, strictly access-controlled. Backed up centrally; schema changes go through managed migrations (Alembic), never ad-hoc edits.

↑aggregated API responses, filtered per user's scope — shown as the direction data travels back up to screens
Stage 5 · Seeing the data

Reporting & Dashboards — the same data, shaped for each audience

Dashboard / Revenue Command Center

  • Live pipeline KPIs, all figures converted to corporate currency
  • Personal widget layout saved per user

Leadership Analytics

  • Period reports across teams & regions
  • Winner/loss trends for management review

Forecast & KPI views

  • Weighted pipeline by stage
  • Monthly KPI scorecards with review trail

Exports & Lead 360

  • Permission-gated CSV export
  • Full history of any single prospect

A manager and an executive opening the same dashboard see different numbers — the scope engine filters at query time, so no screen ever shows data the viewer shouldn't see.
